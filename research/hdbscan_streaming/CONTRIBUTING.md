# Contributing

Thank you for improving the FlowFish reproduction package.

## Before Opening a Change

From `research/hdbscan_streaming/`, run:

```bash
python3 scripts/check_release.py
git diff --check
```

For benchmark changes, also run the smallest relevant reproduction command and
record the output directory in the change description. Do not report a
performance result without the command, input fixture, method configuration,
and artifact path.

## Adding Results

- Keep raw summaries and traces under a new directory in `results/`.
- Do not overwrite a prior run unless the change intentionally regenerates the
  active release bundle.
- Record dataset size, seed, arrival interval, method key, and key quality and
  operational metrics.
- Keep foreground latency separate from background maintenance time.
- Include queue depth, backpressure, and recomputation counts for asynchronous
  methods.
- Do not remove historical results only to make a comparison look better.

The canonical method key for FlowFish is
`adaptive_fishdbc_async`. Use the paper name and code name together when
introducing a new table or figure.

## Data, Models, and Dependencies

Raw FSDD audio is not redistributed by this package. Check
`data/fsdd/PROVENANCE.md` and `THIRD_PARTY_NOTICES.md` before adding an
artifact. Preserve upstream license files when vendoring code.

## Figures and Claims

Figures should be generated by a checked-in script and should include a
corresponding source result file. Keep captions and README text aligned with
the measured metric. Do not claim universal superiority, production
readiness, or cross-domain speaker-recognition quality without matching
evidence.

## Citation

Use `CITATION.cff` for the software citation. Cite the accompanying ICASSP
paper and the upstream FISHDBC work when publishing derived results.
