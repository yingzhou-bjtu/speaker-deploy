# 研究动机与拟议贡献

## 研究动机

在机器人和边缘智能系统中，语音身份识别通常依赖预先进行声纹注册。用户需要先录入自己的语音，系统才能将后续语音匹配到对应身份。这种方式虽然直接，但交互过程不够自然，也容易让用户认为机器人或边缘设备仍然依赖人工配置，影响对系统智能化程度的评价。

理想的机器人语音系统应尽可能无感地识别人。实现这一目标的前置任务不是简单地识别已经注册的用户，而是面向任意输入音频流完成两项工作：

1. **归类**：判断哪些音频片段属于同一个人。
2. **匹配**：判断当前音频片段能否与已有的说话人身份正确对应。

因此，这类系统的评价重点不应只是分对了多少个说话人。更重要的是，在不错误合并不同说话人的前提下，尽可能保持较高的识别准确率。换言之，系统需要优先控制误合并和错误身份输出，同时在证据逐渐积累后提高识别覆盖率。

基于这一动机，当前代码实现了一个无需用户预先完成声纹注册的流式说话人识别 demo。其基本流程为：

```text
音频流
  -> 说话人嵌入提取
  -> 无监督聚类
  -> 稳定说话人身份维护
  -> 与已有身份匹配或生成新的匿名身份
```

## 当前问题

当前 demo 使用 HDBSCAN 对不断积累的说话人嵌入进行无监督聚类。随着输入音频数量增加，系统需要处理的嵌入越来越多，聚类过程逐渐变慢。现有流程基本上是在每次接收新音频后，对当前缓存重新进行聚类，存在较多重复计算。

这个问题会同时影响：

- 单条音频从输入到身份输出的延迟；
- 长时间运行时的计算开销；
- 边缘设备上的 CPU 和内存占用；
- 系统持续运行时的实时性和稳定性。

因此，后续研究需要在尽量不牺牲聚类准确率和身份安全性的前提下，减少 HDBSCAN 对历史音频的重复处理。

## 拟议贡献

### 贡献一：无需声纹注册的流式说话人识别方案

设计一种面向机器人和边缘智能设备的流式说话人识别流程。系统不要求用户在使用前完成显式声纹注册，而是从连续音频流中逐步积累说话人证据，自动完成音频归类，并在满足可靠性条件后建立稳定的匿名说话人身份。

该方案重点关注以下原则：

- 对未知说话人保持开放集处理能力；
- 在证据不足时允许暂不输出身份；
- 避免因为单条或低质量音频造成错误身份合并；
- 随着同一说话人的有效音频增加，逐步提高识别稳定性；
- 将音频聚类和已有身份匹配分开评价。

### 贡献二：面向流式场景的增量缓存 HDBSCAN

针对标准 HDBSCAN 在音频持续到达时需要反复处理历史嵌入的问题，设计一种增量缓存方式的 HDBSCAN。该方法不再对全部历史音频进行无差别的重复聚类，而是维护具有代表性的聚类缓存和必要的局部统计信息。

对于新到达的音频嵌入，系统优先利用已有缓存进行局部匹配和簇状态更新。只有在出现无法归属、簇边界不确定、簇内一致性下降等情况时，才触发必要的局部重计算或簇调整，从而减少冗余计算。

该方法需要重点保证：

- 聚类结果的准确率和身份安全性不低于标准 HDBSCAN；
- 不同说话人之间的错误合并受到控制；
- 输入规模增加时，聚类延迟增长更缓慢；
- 缓存规模和边缘设备资源占用保持有界；
- 增量更新结果与离线全量聚类之间具有可解释的关系。

## 当前研究状态

当前解压代码已经具备流式说话人识别 demo，包括说话人嵌入提取、标准 HDBSCAN 聚类、缓存压缩、稳定身份维护和注册表匹配等模块。实验框架中已经实现一个自适应折中 prototype：它以 Full HDBSCAN 建立代表点缓存，对高置信样本执行快速分配，并在距离、间隔或重算周期触发时恢复 Full。该实现目前证明了工程路径可行，但还不能宣称具有跨数据集的准确率保证。

后续工作需要围绕以下问题展开：

1. 将自适应折中 prototype 形式化为风险感知的流式重聚类算法，明确定义代表点、簇统计量、风险分数和更新规则。
2. 设计标准 HDBSCAN 与增量方法之间的公平比较流程。
3. 在不误合并不同说话人的前提下，评价识别覆盖率和准确率。
4. 测量不同音频规模下的聚类延迟、峰值内存和缓存增长情况。
5. 通过消融实验验证缓存、局部更新、噪声处理和稳定身份约束各自的作用。

当前 idea 审查和实验记录分别见 `HDBSCAN流式折中算法_idea审查.md` 与 `HDBSCAN流式折中算法_实验记录.md`。其中已经区分工程 smoke 证据、可用于论文的结论和仍未验证的范围。

## 备选投稿方向

在不投 **Speech and Language Processing** track 的前提下，暂定保留以下两个 ICASSP 投稿方向：

### 方向一：Machine Learning for Signal Processing（MLSP）

当后续工作能够形成较完整的在线聚类方法时，优先考虑 MLSP。该方向需要将论文核心定位为面向连续嵌入流的风险感知、有界记忆在线聚类方法，重点突出：

- 增量更新或近似密度聚类机制；
- 代表样本、边界样本和簇统计量的有界记忆表示；
- 基于不确定性的快速更新、局部重聚类和全量重建策略；
- 在误合并风险约束下提高识别覆盖率；
- 与全量 HDBSCAN、`approximate_predict`、在线 AHC 和最近原型匹配等方法的比较。

在该定位下，说话人嵌入主要作为连续数据流验证场景，机器人和边缘设备作为应用背景。若选择 MLSP，算法抽象、误差分析和跨场景泛化实验需要达到方法论文要求。

### 方向二：Applied Signal Processing Systems（ASPS）

当最终优势主要体现为真实机器人和边缘设备上的实时处理能力时，考虑 ASPS。该方向重点突出：

- 连续音频流的端到端处理流程；
- 有界缓存和长期运行资源控制；
- 板端 CPU、内存、延迟和稳定性；
- 开放集说话人聚类与已注册身份匹配的系统协同；
- 在真实机器人音频链路中的部署和验证。

在该定位下，论文应将方法描述为面向边缘机器人的风险感知流式说话人归档系统，重点报告端到端性能、资源占用、误合并率、未决比例和长时间运行结果。

### 方向选择原则

- 若在线聚类方法具有明确的算法创新，并且在多个数据集或连续嵌入流任务上有效，优先选择 **MLSP**。
- 若主要贡献是机器人边缘部署、有界资源控制和完整系统验证，优先选择 **ASPS**。
- 两个方向均不应把匿名聚类标签直接表述为现实身份识别。无注册信息时，输出应称为匿名说话人标签；存在注册声纹时，才执行已知身份匹配。
